# Risks - read before flashing

## Your unit
- **Bricking risk is low but not zero.** Only the MAIN OS section is modified; the bootloader (which provides the
  startup-menu OS upgrade) is untouched, so a unit that fails to start can be recovered by sending the official OS
  over **physical MIDI** from the startup menu ([docs/INSTALL.md](docs/INSTALL.md)). Keep a MIDI interface ready.
- **Warranty/support**: modified firmware may void the warranty. Revert to the official OS before any service.
- **Untested builds**: v3o (1.5a), v3p (1.5b) and v3q-spectrum (1.5c) have passed all emulator tests but not yet a hardware test; v3r-all (1.5d) is hardware-confirmed.
  v3n (1.5Z) is the latest hardware-confirmed build.

## Your projects
- Tracks set to POLY store machine value 4. The official OS does not know it and loads such tracks as ONESHOT.
  Back up everything with the manufacturer's transfer app before flashing, and before reverting.
- Stand-alone builds and Digi utilities before 1.7a: Song mode is disabled (songs cannot be played; a project saved
  in song mode opens in pattern mode). Digi utilities 1.7a and later keep Song mode as stock.
- Don't use this OS for gigs until you have tested your own projects on it.

## Technical risks (what could still go wrong)
| area | risk | mitigation |
|---|---|---|
| Audio interrupt hooks (scope tap, voice-start count, POLY per-voice params) | timing overrun or register corruption -> glitches/crash | all hooks preserve registers; verified against the stock interrupt code in emulation; tap adds ~100 instructions per 0.67 ms block |
| MIDI cable (MIDI out task) | stuck POLY note if a note-off is lost | notes are released on the matching note-off; stop/restart sequencer; no panic function yet |
| CC cable | an external CC and a MIDI-track CC arriving at the same instant for the same POLY track (two tasks) | residual race; effect is at most one lost/overwritten value |
| Tuner | CPU use in the UI task (worst ~0.7 M instructions per estimate, every 4th frame) | runs outside the audio interrupt; UI may feel slightly slower with the page open |
| Spectrum (1.5c) | ~0.58 M instructions per analysis (at most one per 21 ms capture) in the UI task; 6 KB allocated once; audio tap copies 32 samples per block only while a capture is requested | allocation failure leaves the page blank; stop by closing the page |
| Memory | scope/tuner data lives in reclaimed code space of removed song-mode screens; tuner allocates 1 KB once | all reclaimed ranges verified unreachable; allocation failure just disables the tuner |
| Knobs through the scope (v3p) | the main screen might not apply knob turns while covered | falls back to stock behaviour if so; close the scope to edit |
| Master EQ page (digieq 1.0a) | the EQ is a page added to the firmware's master view (its page list gets one more entry, kind 0, the firmware's unused "None" page, renamed); an untested path of that view could treat the extra page differently | checked in emulation: page order and counters, knobs, knob presses, LEVEL knob, page changes, leaving and coming back; the other three pages are the stock ones |
| Digi Poly's voice pool in the kit (1.0c) | the setting lives in an unused parameter slot (52) of each track's sound; if a future official OS used that slot, a kit saved here would carry a value it did not expect | the slot is 0 in every kit we have seen and the stock UI never writes it; sounds are copied and stored as one 162-byte block, so it travels with the sound. Take a project backup before flashing, as always |
| Digi Poly chord preview (1.0c) | the track key's extra notes go straight to the audio engine, so they are not recorded and not sent to MIDI OUT | only the note you played is recorded; the chord comes back from NOT2-NOT4 on playback |
| Digi Poly knob mirroring (1.0b) | a knob turn on a POLY track also writes the same value to the stolen voices' parameter copies; the stolen tracks' own sounds are untouched (they reload at their next trig) | checked in digiemu: stolen voices equal the POLY voice after the turns, other voices unchanged |
| Master EQ (digieq 1.0a) | extra work in the audio interrupt: about 5,000-7,300 instructions a block with bands active (measured) (~5 % of the 0.67 ms block at 250 MHz, estimated); with a very busy project that could push the audio over its budget (clicks) | flat bands cost nothing; set bands back to 0 dB (and away from filter types) if you hear clicks; FAST AUDIO (digihealth) gives the render headroom |
| Page on a held "..." (1.7a) | the page is a Song edit screen object with its own copy of the class table; a firmware path that treats it as the real Song edit screen could act on it | only the object opened by the hold is changed; the Song edit screen opened from the popup or a double press is stock (checked in emulation, incl. pattern changes and Song mode on) |
| Master EQ output | boosts can clip the main output | the output is limited to full scale; lower the master volume or cut elsewhere when boosting |
| Digi Poly (digipoly 1.0a): chords by voice stealing | a chord note cuts whatever the stolen track was playing; a stolen track's own trig cuts the chord note; with few free voices notes are skipped | this is how voice stealing works: lock tracks that must never be cut (SETTINGS > POLY), mute tracks you want to lend; drum tracks that trig often are stolen last |
| Digi Poly: engine hooks | the router runs for every note in the audio interrupt and adds messages from the firmware's own pool; a pool running dry skips extra notes | registers kept; checked in digiemu (chords, locks, mutes, live notes); about 200 instructions per note message on average (measured in emulation), well under 1 % of a block |
| Digi Poly: live notes | a lost MIDI note-off leaves a stolen voice held (sequencer trigs of that track are blocked while a live note holds it, as on the stock OS) | send the note-off / stop notes from the sender; the voice is freed as soon as the engine lets it go |
| Digi Poly: TRIG page | the POLY track's TRIG page is the MIDI tracks' page class shown for an audio track; an untested edit path could behave differently from a MIDI track | knob edits and trig-hold locks of NOT1-NOT4, VEL, LEN checked in digiemu; switching the machine back to another one restores the stock page |
| elekloader mods (1.5e) | not yet run on hardware; combined with other people's mods, a problem can come from either side | emulator walk-through with FAST AUDIO on passes; try our two mods alone first, then add others one at a time |
| Digi Matrix's slots in the kit (1.0a) | the 8 routing slots live in two unused parameter slots (46, 47) of each track's sound; if a future official OS used them, a kit saved here would carry values it did not expect | both are 0 in every kit we have seen and the stock UI never writes them. Loading a *sound* onto a track clears that track's slot (the sound brings its own 162-byte block) |
| Digi Matrix: the engine passes | two extra passes over the parameter words in the audio interrupt, around the firmware's own LFO stage; a slot with OWN off takes an LFO off its own destination for that block | registers kept; the borrowed word is put back in the same block and the whole array is rewritten from the settings every block anyway. Idle cost about 350 instructions a block (0.4 %); checked in digiemu (the routing moves the other track's word, and stops dead when the slot is switched off) |
| Digi Matrix: destinations | a destination is a parameter slot of the destination track; the SRC page's eight slots mean different things per machine, so `SRC.A`..`SRC.H` follow whatever that track's machine puts on those knobs | the page names destinations by page and knob rather than guessing the machine's own names; pick the destination with the track's own SRC page in front of you |
| Digi EQ on the master mix (1.0a) | the EQ now runs on the master pair before it is spread over the outputs, so a mistake there is heard on every output at once instead of the analog ones only | the buffer, its length and its scale were measured in the emulator (a test signal put in comes back out of both the analog path and the USB bus); the hook keeps every register and the EMAC state, and the block is processed in place with the same clamp as before |
| Digi EQ's settings in the kit (1.0a) | the four bands live in two unused parameter slots (48, 49) of the first four tracks' sounds; if a future official OS used them, a kit saved here would carry values it did not expect | both are 0 in every kit we have seen and the stock UI never writes them; a kit without the marker bit reads as "no EQ". Loading a *sound* onto tracks 1-4 clears that band |
| Digi EQ global override (1.0a) | with SETTINGS > GLOBAL FX/MIX > MASTER EQ on, every pattern the unit reaches is given the current EQ settings - that changes those patterns' kits | it is what the setting is for (the same idea as the firmware's own entries); turn it off to leave patterns alone, and the change only becomes permanent when you save the project |
| Digi Poly: recording notes (1.0d) | the notes are written into the step after the firmware has recorded the trig, from a hook inside its record path; a step that gets one note has its NOT2-NOT4 cleared, so the track's default chord no longer applies to that step | that is what recording what you played means; the step's notes can be edited on the TRIG page as on a MIDI track, and a step with no recorded note still uses the track's defaults |
| Digi Poly: the TRIG page's LEVEL knob (1.0d) | the page kind is put back to the audio one for the length of the stock knob call, so the firmware answers "track level" | only for the LEVEL knob, only on a POLY track, and only around that one call; every other knob goes straight to the stock handler (checked in tests/emu_poly.py) |
| Per-pattern settings and the +Drive (all three mods) | Since 2.0d Digi Poly's voice pool, Digi Matrix's slots and Digi EQ's bands are kept in six bytes of each sound record that the firmware saves and loads but does not use (a reserved long at the start and parameter slot 0; zero in all 1024 sound records on the +Drive). If the firmware did use them somewhere not exercised in the emulator, a setting could be lost or a sound could change. Sounds saved from a track to the pool carry these bytes along; the stock OS ignores them | round trip (save, wipe, load) and edits (LEVEL, sample, all SRC/FLTR/AMP/LFO knobs) measured in the emulator; reads traced during play; a sound loaded onto a track is handled (the mods put their bytes back); on the unit, check once after a power cycle that a pattern's pool, matrix and EQ came back |
| Unknown | untested combinations (the manufacturer's USB audio/control software, sample transfer while the scope is open, long sessions) | report issues; revert if in doubt |
